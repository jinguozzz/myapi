## 详解

### 1. 目录结构规划

参考需求文档中「技术选型」与「UI/UX 设计」，采用分层架构：

- `core/`：跨层基础设施（常量、主题、路由、工具）。
- `models/`：数据模型（ModelConfig、Conversation、Message，对应文档第 6 章）。
- `providers/`：状态管理（对应 Riverpod，覆盖模型 / 对话 / 设置三块）。
- `services/`：服务层（存储、网络、日志，对应 Hive + SQLite + Secure Storage + Dio + SSE）。
- `pages/`：页面层（四个底部 Tab：对话、历史、模型管理、设置，对应文档第 5.1 节）。

```
lib/
├── main.dart / app.dart
├── core/    (constants, theme, router, utils)
├── models/
├── providers/
├── services/ (storage, network, logger)
└── pages/   (home, chat, history, models, settings)
```

### 2. 占位类文件

每个模块文件仅包含一个空的类定义与注释，未引用任何第三方依赖，保证不引入编译错误。例如：

命名说明：设置页的「关于」弹窗命名为 `AboutInfoDialog`，避免与 Flutter 内置 `AboutDialog` 冲突。

### 目标

### 改动文件

| 文件 | 改动 |
| --- | --- |

- **Gradle 发行版镜像（腾讯云）**：`distributionUrl` 由 `services.gradle.org` 改为 `mirrors.cloud.tencent.com/gradle`，避免下载 Gradle 9.1.0 卡在国外服务器。

### 验证结果

7. **新建对话**：创建新会话并写入库，旧会话保留在历史中（此前为直接清空）。

## 第九部分：内存泄漏与存储占用审计修复

### 审计结论

对全部 `AnimationController / TextEditingController / Timer / StreamSubscription / addListener` 逐项核查：控制器、定时器、动画控制器、流订阅均已在 `dispose()` 中释放，未发现明显泄漏。修复了以下存储与资源问题。

### 修复项

| 问题 | 文件 | 处理 |
| --- | --- | --- |
| 单会话消息无上限，内存与数据库无限增长 | `chat_page.dart`、`conversation_repository.dart` | 消息上限 200 条：内存侧流式时裁掉最旧；数据库每轮结束后 `trimMessages()` 裁剪最旧行（对应需求文档风险项「限制对话最大消息数」） |
| 导出 .md 临时文件累积占用缓存 | `history_page.dart` | 每次导出前清理缓存目录下旧的 `.md` 临时文件 |
| 空会话（0 消息）堆积 | `app_state.dart`、`conversation_repository.dart` | 启动时 `deleteEmptyConversations()` 清理无消息会话 |
| 搜索/加载竞态（快速输入导致旧结果覆盖） | `history_page.dart` | `_loadToken` 令牌守卫，只采纳最新一次结果 |
| 重命名弹窗控制器未释放 | `history_page.dart` | `showDialog().whenComplete(ctrl.dispose)` |
| `app.dart` 每次 build 重建合并监听器 | `app.dart` | 提升为 `static final _appListenable` |

### 保留的设计

- `AppState` 单例（含模型/会话列表）与应用同生命周期，属预期占用。
- `HomePage` 用 `IndexedStack` 常驻四个 Tab，保持对话状态，非泄漏。
