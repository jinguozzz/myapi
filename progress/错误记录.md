## E-001 DeepSeek API 模型名错误

**日期**：2026-08-16
**状态**：已修复
**涉及模块**：对话聊天（真实 API 请求）/ 模型管理

### 原始错误（备份）

在模拟器中配置真实模型密钥后进行对话，流式请求返回以下错误：

```json
{
  "error": {
    "message": "The supported API model names are deepseek-v4-pro or deepseek-v4-flash, but you passed 4.",
    "type": "invalid_request_error",
    "param": null,
    "code": "invalid_request_error"
  }
}
```

### 复现场景

1. 在「模型」页添加模型，填写显示名称、Model ID、API Base URL、API Key。
2. 在对话页发送消息。
3. 服务端返回上述错误，App 将错误信息渲染在 AI 气泡中。

### 原因分析

- 应用请求 `POST {baseUrl}/chat/completions`，请求体 `model` 字段直接取「Model ID」输入框原文（见 `lib/services/network/chat_service.dart` 的 `'model': model.modelId`）。
- 用户配置时 Model ID 填写为 `4`，非 DeepSeek 支持的模型名，服务端拒绝请求。
- 根因是配置引导不足（用户对「Model ID」含义不明确），非代码逻辑缺陷。

### 修复措施

- 在「添加/编辑模型」弹窗（`lib/pages/models/widgets/model_edit_dialog.dart`）新增**快捷预设**：
  - DeepSeek V4 Flash（`deepseek-v4-flash`）
  - DeepSeek V4 Pro（`deepseek-v4-pro`）
  - OpenAI GPT-4o（`gpt-4o`）
  - 智谱 GLM-4（`glm-4`）
  - 点击自动填充「显示名称 / Model ID / API Base URL」，仅需再填 API Key。
- Model ID 输入框增加辅助说明：「即请求体中的 model 参数，如 deepseek-v4-flash」。

### 用户侧处理

将已有模型的 Model ID 改为合法值（如 `deepseek-v4-flash`）即可恢复正常。

### 经验教训

- 第三方 API 参数应提供明确的输入引导与预置模板，降低误配概率。
- 建议后续增加「测试连接」按钮，保存前即可验证配置是否可用。
